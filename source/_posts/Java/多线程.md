# 关于多线程的几个使用场景

1.  多个线程操作不同的资源
    
2.  多个线程操作一个资源（也就是并发）
    
    > 并发有可能导致线程不安全，解决方法就是线程同步，线程同步涉及到锁和线程通信
    > 
    > 生产者消费者就是典型的并发导致的线程不安全问题，通过线程同步来解决
    
3.  一个线程内也就不存在并发问题
    

# 进程与线程

进程：系统资源分配的基本单位，一个进程可以包含多个线程

线程：CPU调度和执行的基本单位

> 1.  线程就是独立的执行路径
> 2.  main()称之为主线程，为系统的入口，用于执行整个程序
> 3.  多个线程的运行由调度器安排调度，与操作系统密切相关，不能人为干预
> 4.  对同一份资源操作时，存在资源抢夺的问题，需要加入并发控制
> 5.  线程带来额外的开销：cpu调度时间；并发控制开销
> 6.  **每个线程在自己的工作内存交互，内存控制不当会造成数据不一致**

## 继承Thread类（重点）

1.  自定义线程类继承Thread类
2.  重写run方法，编写线程执行体
3.  创建线程对象，调用start()方法启动线程

```java
//创建线程方式：1.继承Thread类 2.重写run方法 3.调用start开启线程

public class TestThread extends Thread {

    public void run() {
        //2.run方法线程体

        }

    }

    public static void main(String[] args) {
        //main线程，主线程

        //创建一个线程对象
        TestThread testThread = new TestThread();

        testThread.start();//和主线程交替执行
```

案例4：多个线程操作一个对象（存在线程不安全的情况）【模拟龟兔赛跑】

```java
//模拟龟兔赛跑
public class MultiThreadForRace implements Runnable {

    //胜利者
    static String winner;
    @Override
    public void run() {
        for (int i = 0; i <= 100; i++) {
            //模拟兔子休息
            if(Thread.currentThread().getName().equals("兔子")&&i==99){
                try {
                    Thread.sleep(1);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            }

            //判断比赛是否结束
            boolean flag=gameOver(i);//设置标志位终止线程
            //如果比赛结束了就停止程序
            if(flag){
                break;
            }

            System.out.println(Thread.currentThread().getName() + "-->跑了" + i + "步");
        }
    }

    //判断是否完成比赛
    private boolean gameOver(int steps){
        //判断是否有胜利者
        if(winner!=null){//已经存在胜利者了
            return true;
        }else{
            if( steps>=100){
                winner=Thread.currentThread().getName();
                System.out.println("Winner is " + winner);
                return true;
            }
        }
        return false;
    }
    public static void main(String[] args) {
        MultiThreadForRace race = new MultiThreadForRace();
        new Thread(race,"兔子").start();
        new Thread(race,"乌龟").start();
    }
}
```

## 实现Callable接口

1.  实现Callable接口，需要返回值类型
2.  重写call方法，需要抛出异常
3.  创建目标对象
4.  创建执行服务`ExecutorService executorService = Executors.newFixedThreadPool(3);`
5.  提交执行`Future<Boolean> submit = executorService.submit(t1);`
6.  获取结果`Boolean aBoolean = submit.get();`
7.  关闭服务`executorService.shutdownNow();`

# 静态代理模式

1.  真实对象和代理对象**都要实现同一个接口**（线程创建中实现Runable接口，就是使用了代理模式）
2.  代理对象要代理真实角色

好处：

1.  代理对象可以做很多真实对象做不了的事情
2.  真实对象专注做自己的事情

帮助理解案例

```java
public class StaticProxy {
    public static void main(String[] args) {
        You you = new You();//你要结婚
        new WeddingCompany(you).HappyMarry();//这里you就是真实对象，WeddingCompany对象就是代理对象
    }
}

interface Marry{//共同实现了这个接口
    void HappyMarry();
}

//真实角色，你去结婚
class You implements Marry{

    @Override
    public void HappyMarry() {
        System.out.println("秦老师要结婚了");
    }
}

//代理角色，帮助你结婚
class WeddingCompany implements Marry{

    private Marry target;//这就是真实对象

    public WeddingCompany(Marry target) {//真实对象在构造方法中初始化
        this.target = target;
    }

    @Override
    public void HappyMarry() {
        before();
        this.target.HappyMarry();//这就是真实对象
        after();
    }

    private void after() {
        System.out.println("结婚之后收尾款");
    }

    private void before() {
        System.out.println("结婚之前布置现场");
    }
}
```

## 线程停止

1.  建议线程正常停止—>利用次数，不建议死循环
2.  **建议使用标志位**—>设置一个标志位
3.  不要使用stop或者destory等过时或者JDK不建议使用的方法

```java
/*测试stop
1.建议线程正常停止--->利用次数，不建议死循环
2.建议使用标志位--->设置一个标志位
3.不要使用stop或者destory等过时或者JDK不建议使用的方法*/
public class TestStop implements Runnable{
    private boolean flag=true;//1.设置标记

    @Override
    public void run() {
        int i = 0;
        while (flag){//2.判断标记
            System.out.println("线程正在运行"+i++);
        }
    }

    public void stop(){//3.改变标记的方法
        this.flag=false;
    }

    public static void main(String[] args) {
        TestStop testStop = new TestStop();
        new Thread(testStop).start();

        for (int i = 0; i < 1000; i++) {
            System.out.println("main" + i);
            if(i==900){
                testStop.stop();//4.调用改变标记的方法
                System.out.println("线程该停止了");
            }
        }
    }
}
```

2.  调用sleep方法，线程会阻塞，时间到进入就绪状态，之后进入运行状态
3.  模拟网络延时：放大问题的发生性。`Thread.sleep()`

## 观测线程状态

线程状态。线程可以处于以下状态之一：

-   `NEW`  
    新生：尚未启动的线程处于此状态。
    
-   `RUNNABLE`
    
    运行：在Java虚拟机中执行的线程处于此状态。
    
-   `BLOCKED`
    
    阻塞：被阻塞等待监视器锁定的线程处于此状态。
    
-   `WAITING`  
    死死地等待：正在等待另一个线程执行特定动作的线程处于此状态。
    
-   `TIMED_WAITING`  
    超时等待：正在等待另一个线程执行动作达到指定等待时间的线程处于此状态。
    
-   `TERMINATED`  
    终止：已退出的线程处于此状态。
    

一个线程可以在给定时间点处于一个状态。 这些状态是不反映任何操作系统线程状态的虚拟机状态。

`thread.getState();`方法可以查看当前线程状态

## 线程优先级

1.  范围：\[1-10\]，默认是5
2.  使用方法：`thread.setPriority(1);`设置优先级；\`\`thread.getPriority()\`获取优先级
3.  优先级的设定建议在start()调度前
4.  优先级低只是意味着获得调度的概率低，并不是优先级低就不会被调用了，这都是看CPU的调度

## 守护线程Daemon

1.  分类：线程可分为用户线程和守护线程
2.  用户线程：正常的线程都是用户线程；虚拟机必须确保用户线程执行完毕
3.  守护线程：使用`thread.setDaemon(true);`设置为守护线程，默认是false；虚拟机不用等待守护线程执行完毕（即虚拟机早于守护线程结束）

# 线程同步

并发：公共资源被多个线程同时操作（可能存在线程不安全问题）

线程同步：解决方案—>队列+锁—>synchronized关键字

## synchronized关键字：

> 1.  synchronized方法：synchronized方法默认锁的是this，也即方法的调用者。
>     
> 2.  synchronized块：
>     
>     > 1.  使用方法：`synchronized(对象){被锁对象相关代码块}`
>     > 2.  **注意要保证只有一把锁，即锁的对象不能变，只有一个。（因此这个对象可以是final修饰的字符串或者其他的能够保证多线程访问时该对象不会变的对象，通常用Object.class）**
>     > 3.  方法块的范围：方法里面**公共资源（临界区）内容才需要锁**，锁的太多，浪费资源。**保证了是同一把锁之后，同步代码块的范围才是保证线程安全具体逻辑的关键**
>     > 4.  **总结：锁的对象决定了是不是同一把锁，锁的内容决定了哪些代码块用于被同步**
>     

## 可重入锁ReentrantLock类

ReentrantLock类实现Lock接口，手动开启和关闭锁，**别忘记关闭锁**，与synchronized相比性能更好

使用方法：关闭锁通常放在finally语句中，保证锁可以被关闭

一般设置成private final,也要保证锁的唯一性(写在资源类的属性位置,保证全局的唯一性，若写在方法中，将失效)

```java
//**并发：多线程操作同一个资源类，把资源丢入线程**

//A为一个资源类
class A{
    //一般设置成private final,也要保证锁的唯一性(写在资源类的属性位置,保证全局的唯一性，若写在方法中，将失效)
    private final ReentrantLock lock=new ReentrantLock();
    
    
    public  void m() {
        lock.lock();//开启锁
        try{
            //保证线程安全的代码
        }finally {
            lock.unlock();//关闭锁
            //如果同步代码有异常，要将unlock()写入finally语句块
        }
    }
}
```

# 死锁

1.  互斥条件： 一个资源一次只能被一个进程使用
2.  请求与保持条件：一个进程因请求资源而阻塞时，对已获得的资源保持不放
3.  不剥脱条件：进程已获得的资源，在未使用完之前，不能强行剥夺
4.  循环等待条件：若干进程之间形成一种头尾相接的循环等待资源关系

只要破坏其中一种或多种就可以避免死锁的发生

# 线程协作

Java提供了几个方法解决线程之间的通信问题

方法名

作用

wait()

表示线程一直等待 ，直到其他线程通知，与sleep不同，会释放锁

wait(long timeout)

指定等待的毫秒数

notify()

唤醒一个处于等待状态的线程

notifyAll()

唤醒同一个对象上所有调用wait()方法的线程，优先级别高的线程优先调度

**注意:均是0bject类的方法，都只能在同步方法或者同步代码块中使用，否则会抛出异常llegalMonitorStateException**

```java
    }
}

//消费者
class Consumer extends Thread {
    SynContainer container;

    public Consumer(SynContainer container) {
        this.container = container;
    }

    @Override
    public void run() {
        for (int i = 0; i < 100; i++) {
            System.out.println("消费了第--->" + container.pop().id + "只鸡");
        }
    }
}

//产品
class Chicken {
    int id;

    public Chicken(int id) {
        this.id = id;
    }
}

//缓冲区
class SynContainer {

    Chicken[] chickens = new Chicken[10];//容器大小
    int count = 0;//

    //生产者放入产品
    public synchronized void push(Chicken chicken) {
        //如果容器满了，需要等待消费者消费
        if (count == chickens.length) {
            //通知消费者消费，生产者等待
            try {
                this.wait();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }

        //如果没有满，我们就需要丢入产品
        chickens[count] = chicken;
        count++;

        //可以通知消费者消费了
        this.notifyAll();

    }

    //消费者消费产品
    public synchronized Chicken pop() {
        //判断能否消费
        if (count == 0) {
            //等待生产者生产，消费者等待
            try {
                this.wait();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }

        //如果可以消费
        count--;
        Chicken chicken = chickens[count];

        //吃完了，通知生产者生产
        this.notifyAll();
        return chicken;
    }
}
```

# 线程池

提前创建好多个线程，放入线程池中，使用时直接获取，使用完放回池中。可以避免频繁创建销毁、实现重复利用。

JDK 5.0起提供了线程池相关API: ExecutorService 和Executors

Executors: 工具类、线程池的工厂类

> 1.  用于创建并返回不同类型的线程池
> 2.  用于生成ExecutorService实例对象。

ExecutorService接口具体使用如下:

> 1.  ExecutorService: 真正的线程池接口。常见子类ThreadPoolExecutor
> 2.  void execute(Runnable command) :执行任务/命令,没有返回值，一般用来执行Runnable
> 3.  Future submit(Callable task):执行任务,有返回值，一般用来执行Callable
> 4.  void shutdown() :关闭连接池

```java
public class TestTheadPool {
    public static void main(String[] args) {
        //创建服务，创建线程池，参数为线程池大小
        ExecutorService executorService = Executors.newFixedThreadPool(10);
        //执行
        executorService.execute(new A());
        executorService.execute(new A());
        executorService.execute(new A());

        //关闭连接
        executorService.shutdownNow();
    }
}

class A implements Runnable{

    @Override
    public void run() {
        System.out.println(Thread.currentThread().getName());
    }
}
```
